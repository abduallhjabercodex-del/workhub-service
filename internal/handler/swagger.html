Test Scenarios

1 Login as Owner, then view projects and tasks
  1. Open POST /api/v1/auth/login and execute with owner@workhub.dev / Password1234!.
  2. Copy the accessToken from the response.
  3. Click Authorize above and paste token as Bearer <token>.
  4. Execute GET /api/v1/projects.
  5. Execute GET /api/v1/projects/1/summary.
  6. Modify a task via PATCH /api/v1/tasks/2 with a new status.
Expected 200 OK All 3 seeded projects returned and task update succeeds.
2 RBAC Enforcement — Reject Viewer modifications
  1. Login via POST /api/v1/auth/login using viewer@workhub.dev / Password1234!.
  2. Set the accessToken in the Authorize modal.
  3. Attempt modifying a task via PATCH /api/v1/tasks/1 to status done.
Expected 403 Forbidden Viewer role lacks write permissions.
3 Last Owner Guard — Prevent removing final Owner
  1. Login as owner@workhub.dev and click Authorize.
  2. Execute DELETE /api/v1/projects/1/members/1 (attempt removing the sole owner).
Expected 409 / 422 Server rejects operation to protect last project owner.

💡 Tip: After switching accounts, remember to update the token in Authorize. Swagger UI preserves the token across page reloads.
